TITOLO BASI DI WEB

Tutto il web funzione con una architettura client-server
	*server ospita informazioni organizzandole in siti web rendendole
	disponibili ai client
	* i client sottoponono di norma richieste di informazioni http/https
		+ le informazioni ossono essere di molteplici tipi

				*WORLD WIDE WEB*

Definito al CERN negli anni 90, ma è precedente
Da' accesso multimediale alle informazioni --> non solo testo ma anche
immagini/video/suono...
Ogni nodo della infrasruttura è un sito/pagina/servizio web ed essi sono
connessi in una sete in un server.
Ogni server è a sua volta una nodo di una rete più grande

Inizialmente per lo scamio di dati ci si appoggiava principalmente all'FTP, 
ora è praticamnte morto

La crescita di hostname e siti ha seguito un trend di crescita LOGARITMICO

I servizi web stanno pian piano sostituendo il programma in locale con una
versione online (aggiornamento unico ma per tutti)

Il WWW aiuta l'umanità ad avere accesso alle informazioni
Attualmente ci sono più di 4 MILIARDI di utenti

Il WWW è solo una tipologia di applicazione web, ma è la più usata
Fornisce accesso a documenti IPERTESTUALI attraverso internet
	+ anche media non solo file

			*WEB SERVER E WEB BROWSER*

Server:	
	* contiene le informazioni
	* le mette a disposizione
	* programma in ascolto su una porta TCP
		+ quando riceve una richiesta
			# la analizza
			# prepara la risposta
			# invia la risposta
				§ può essere affermativa
				§ può essere una richiesta di reinvio
Client:
	* fa richieste al server e riceve risposta
		+ interpreta le informazioni che il server gli fornisce
		+ reinvia la precedente richiesta se gli viene domandato
	* non gli importa se lui non riceve tutte le risposte


			*DA DOVE IL SERVER PRNDE LE INFORMAZIONI?*

Dal DB!
Il terzo attore nella architettura è il DBM

					*URL*

Unifrom Resource Locator
E' l'inidirizzo UNIVOCO di OGNI Server

schema://hostname[:port]/path[? query]

					*URI*

Unifrom Resource Identifier
Tipo l'URL ma è più generale --> URL è una sua parte
Ha un set di caratteri ristretto
Sintassi universale
Non definisce la semantica della risorsa

schema://user_info@host.com:port/path/to/data?query#fragment
	'----------------------'	    |
	|	   |			    |
	|	   '-> authority	    |
	'-----------------------------------'
		   |
		   '-> hierarchical part

user_info --> username:password DEPRECATO
query     --> key=vale
fragment  --> fragid...


				*IL WEB SERVER*

Espone parzialmente il suo FS all'Internet


				*CONNESSIONI HTTP*

Ad una richiesta è possibile passare parametri
	* GET:
		passa i parametri in chiaro
	* POST:
		passa i parametri non in chiaro per VALORE (eventualmente
		criptati)

Tipi di connessioni:
	NON PERSISTENTI
		apre e chiude la connessione client-server per ogni risorsa
	PERSISTENTI
		chiude la connessione quando tutte le risorse sono state
		esaudite

				*RICHIESTE HTTP*

La prima riga contiene 
	* campo metodo (GET/POST/HEAD)
	* campo url
	* campo verisone

le righe successive contengono:
	* host
	* tipo di connessione TCP
	* ...

				*RISPOSTE HTTP*

La prima riga contiene:
	* verisone
	* protocollo
	....
Le righe successive conetngono
	....

				*STATELESSNESS*

HTTP è senza stato --> non si conserva NESSUNA informazione sullo stato di
esecuzione --> NON vuole dire che non ci sia persistenza di informazioni fra
pagine della applicazione

Per la persistenza dei dati sono stati crwati due metodi:
	* cookie: il client ricorda attraverso piccoli documenti di testo
	* sessione: il serve si segna le informazoni

				   *COOKIE*

Previsti da http
tenuti dal client
il browser manda i cookie necessari al server (non solo i necessari)

Composti da:
	stringhe si testo
	date di scadenza
	pattern per riconoscere il dominio di origine

Sono temporanei o persistenti
	* temporanei scadono alla chiusura del browser
	* persistenti scadono alla scadenza del cookie stesso

				*WEB STATICO e DINAMICO*

Statico:
	Iformazuoni FISSE su solo file ipertestuali
Dinamico:
	Si aggiunge una parte che fa variare la pagina in base alle azioni degli
	utenti
	Permette anche di accedere alle informazioni lato server, come i DB

interprestazione del testo in maniera indipendente dalla applicazione
Delegano l'interpretazione al browser

Un file html può essere aperto con un un editor o un browser
	* con un editor si vede il dna
	* con un browser si vede la creatura

Case Unsensitive <font> e <FONT> sono uguali
Space Unsensitive <h1> HELLO		sarà sempre HELLO WORLD
			WORLD </b1>
		per andare a capo si usa il tag apposito <br>
